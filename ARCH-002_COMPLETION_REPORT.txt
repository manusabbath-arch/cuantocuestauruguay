🚀 DEPLOYMENT STRATEGY
═════════════════════════════════════════════════════════════════════════════════

  Request Flow
  ├─ Request → /api/v1/etl/run?shadow_mode=false&user_id=...
  │
  ├─ Feature Flag Check
  │  ├─ DISABLED: Use v1 only (100% users)
  │  ├─ SHADOW: Run v1 + v2 parallel, return v1, log v2
  │  ├─ CANARY: % of users → v2 (deterministic by hash)
  │  ├─ GRADUAL: % of users → v2 (increasing percentage)
  │  └─ FULL: Use v2 only (100% users) ✅
  │
  └─ Response: {"source": "v1"|"v2", "result": {...}}

  3-Week Rollout Timeline
  ├─ PHASE 1 (Week 1): 10% users
  │  ├─ Monitoring: Hourly
  │  ├─ Shadow Mode: ACTIVE
  │  └─ Decision: 0 mismatches? → Continue
  │
  ├─ PHASE 2 (Week 2): 25% users
  │  ├─ Monitoring: Every 4 hours
  │  ├─ Manual Validation: 5 data samples
  │  └─ Decision: Perfect match? → Continue
  │
  ├─ PHASE 3 (Week 3): 50% → 100% users
  │  ├─ Monitoring: Daily
  │  ├─ Performance Benchmark: Compare p95, memory
  │  └─ Decision: All metrics OK? → Full deployment
  │
  └─ POST-DEPLOYMENT (Day 30+): Archive v1, cleanup
